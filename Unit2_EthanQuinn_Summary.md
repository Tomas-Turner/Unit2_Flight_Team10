This project highlighted several important realities about modeling highly imbalanced classification problems. The diverted–flight label occurred extremely rarely in the dataset, and this imbalance had a major influence on the model’s behavior and on how the metrics needed to be interpreted. The main insight was that accuracy was essentially meaningless in this setting. Both the baseline and engineered models produced very high accuracy simply because almost every flight was labeled “not diverted.” As a result, metrics such as precision, recall, F1 score, and ROC AUC were far more informative.
Another key takeaway was the influence of the decision threshold. With the default 0.5 threshold, the models predicted “not diverted” for nearly every case, leading to zero recall and zero precision for the diverted class. The model was technically “accurate,” but it failed completely at identifying the minority class. After evaluating multiple thresholds, I set the threshold to 0.20. This value produced the first meaningful trade-off—identifying at least some positive cases—while still keeping false positives to a manageable level. This change reinforced that threshold selection is not optional in imbalanced problems; it is an integral part of model design.
Regarding model performance, the engineered model did not substantially outperform the baseline. Although it incorporated additional features such as route, day of week, and a bucketed version of dep_delay, the overall evaluation metrics remained similar. ROC AUC shifted only slightly (approximately 0.697 for the baseline vs. ~0.680 for the engineered model), and accuracy remained almost identical. The engineered model did provide a marginal improvement in log loss, suggesting its probability estimates were slightly better calibrated, but this improvement did not translate into higher predictive power for the diverted class.
The model’s primary failure point was recall. Even with the reduced threshold, the number of correctly identified diverted flights remained extremely small. This limitation is largely driven by the data itself. Diversions are influenced by operational disruptions, weather patterns, and external variables not available in the dataset. With so few diverted observations and with several important signals missing altogether, the model’s ability to generalize was inherently constrained.
If deployed operationally, a threshold near 0.20 would be most appropriate. False negatives carry a higher operational cost than false positives in this context, so the threshold should bias toward sensitivity, even if that means accepting more false alarms.
Overall, this project underscored the importance of understanding class imbalance, evaluating the right metrics, tuning thresholds deliberately, and recognizing when data limitations—not modeling technique—define the ceiling of achievable performance.
